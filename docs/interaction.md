# Interaction: can an LLM do what a human does, faithfully?

`docs/observation.md` answers the seeing half: an LLM country sees nearly every panel. This
file answers the acting half, one row per action a player takes on a panel (HOI4 1.20), with the
route that does it and whether that route is faithful.

**Faithful** means the same cost and the same conditions as the screen, and never a cheat that
skips time or cost. An effect such as `complete_national_focus`, `set_technology`,
`create_wargoal` or `upgrade_intelligence_agency` does the thing without the days, points or
political power a player pays, so it is a different game and is refused, not used. Where an
effect would skip an answer the other side owes (military access, a pact), the same applies.

## The routes

| Route | What it is | Faithful because |
|---|---|---|
| **Seat, console/inbox** | The LLM holds the player's seat and the harness writes a guarded effect (`adapters/console.py`; `inbox.py` delivers it in-game with no input). | The `limit` copies the game's own `allowed` / `visible` / `available` blocks verbatim, the political power cost is tested in it and taken after it, and a marker is logged inside it, so the log line is the proof the game let it through (`_verify_click`). Pattern: `modcontext/execute.py` (decisions), `policy_effects.py` (laws, occupation, diplomacy). |
| **Seat, UI path** | Mouse and keyboard: `adapters/input_driver.py` and its `ui_scripts`, `production_ui.py`, `unit_orders.py`, `hands.py` (battle plans). | It is the screen. Calibration-bound; only what is recorded exists (`profiles/ui_scripts.*.json`). |
| **Rival, inbox effect** | A country the game's AI runs (`game_ai` preset: politics and steering for the LLM, the rest the AI's). Same guarded effects, delivered through the inbox. | As the seat route. |
| **Rival, steering** | `ai_strategy` blocks in the mod keyed on a country flag (`mod/llm_bridge/common/ai_strategy/*`), generated by `modgen.py`, `front_orders.py`, `steering.py`; the inbox sets the flag. | The AI does the thing itself, with its own acceptance, timing and costs. Tokens and value scales are `common/ai_strategy/_documentation.md` (1.20). Preferences, not orders: the AI still needs the factories, slots and time. |

The control map (`control.py`): the new politics actions are in the `politics` domain (the AI
leaves it to the player: `game_ai` keeps `politics=llm`), the `steer_*` actions are in `STEER_ACTIONS`
(on while `steer=llm`). `diplomacy_act` sits in `politics` on purpose: guaranteeing a country or
leaving a faction needs nobody's answer, so it stays the LLM's when the AI holds `diplomacy`.

**What "mock only" means.** Six catalog tools have an executor only in the simulator (`adapters/mock.py`):
`deploy_divisions`, `set_trade`, `set_army_order`, `set_air_mission`, `set_naval_mission` and `diplomacy`.
No effect does them faithfully and no UI path is recorded, so a live adapter never offers them (the tool
list is the adapter's `supported_actions`), and their catalog descriptions now say "Simulator only"
(`catalog.MOCK_ONLY`). Earlier rows of this table that said "`diplomacy` (mock only live)" in the seat column
described a tool the live game does not have; they now say so, and their status is the refusal and the steering
route, not a seat route. `design_division_template`, which used to be on that list, has a real executor now
(row 50).

Statuses: **have** (before this work), **built now** (this branch), **feasible, not built** (a faithful
route exists, left out; the reason is given), **not feasible** (no faithful route; why).

## Coverage against the independent audit (122 player actions)

An audit (`C:/dev/audit-table.md`, outside the repo) walked 122 actions a player takes against this harness:
35 covered, 21 steered only, 11 refused, 55 missing. The table below is the same 122 rows after the second pass. The classes:

* **covered**: a faithful route exists for the seat (the effect or the UI path), as in the first table.
* **steered only**: the game's own AI does it when told to (`steer_*`, `set_ai_directive`, `set_region_order`); no
  seat route.
* **refused**: an effect exists and would skip a cost, a wait or the other side's answer; the tool refuses with the
  reason (and the steering route, if any).
* **needs recording**: only the mouse reaches it (designers, the deployment screen, generals, task forces, the
  production screen's details, the market and agency screens); a UI script has to be recorded in a live session.
  Nothing is offered meanwhile, and nothing pretends to be.
* **missing**: no faithful route known (no effect, no token with documented syntax, or the other side's answer), or
  built on another branch (the event rows 1, 2 and 4).

Now: **43** covered, **33** steered only, **13** refused, **24** needs recording, **9** missing (122); rows 39 to 41 moved from needs recording to covered with the designers (`docs/designers.md`). Before: 35 covered, 21 steered only, 11 refused, 55 missing. Row 119 and row 48 are mixed rows: the seat route covers the part

## Counts

steered counts once. "Built now" includes row 32 (`ally` joined the six existing directives) and the
refusal rows 25 to 31 and 36: a verb that used to fail in the UI path or silently do nothing now says

## What was built and how it is guarded

* **`hire_advisor`** (`policy_effects.plan_advisor`). As `change_law`: the role's own `allowed`, `visible` and
  `available` blocks (`ModContext.advisor_conditions`, the last file that defines the character wins), `has_political_power`,
  `NOT has_idea` of the token, a marker. Refused: an advisor `allowed` rules the country out of, a condition that reads
  `FROM` or tests the character (`has_character_flag`, `is_hired_as_advisor`, `not_already_hired_except_as`, `has_trait`,
  `is_country_leader`), roles of one character with different conditions and no `slot`. The telemetry read-back
  still decides when no log line can be found (`STATE_FALLBACK`). The result lists the cost modifiers it does not apply.
* **`set_production`** now tests the unlock: `has_tech` for each technology whose `enable_equipments` names the equipment.
* **`take_decision`**: a cost the decision's own effect pays (a negative `add_command_power`, `add_manpower`, `add_*_experience`)
  needs a `custom_cost_trigger` in the guard, or the decision is refused (33 of 4,297 in the vanilla files); with one it is
  guarded and the result says the effect pays it. Cost modifiers are named, not applied: the base cost is charged.
* **`queue_province_building`** (`console._plan_province_building`): row 74.
* **`design_division_template`** (`console._plan_template`): row 50.
* **`design_equipment`** (`console._plan_design`, `designers.plan_design`), **`list_designs`** and
  **`describe_design_option`**: rows 39 to 41, `docs/designers.md`. One `if` in the country's scope: the designer's
  DLC (`has_dlc`), `has_tech` for the chassis and each changed module, `has_<army|navy|air>_experience > cost`;
  body `create_equipment_variant` then the negative experience effect, then the marker. Slots, allowed categories
  (including what a turret opens), count limits, required slots and upgrade levels are checked harness-side and
  refused with the reason. A module nothing unlocks is refused, not guessed.
* **`set_occupation_law state=`** (`policy_effects.plan_occupation_law`): row 65.
* **`steer_spending`, `steer_market`, `steer_army`** and the new kinds of `steer_production` and `steer_intelligence`
  (`steering.py`): rows 12, 13, 18, 23, 47, 51, 69, 70.
* **`change_law`** (`policy_effects.plan_law`). One `if` in the country's scope. `limit`: the new law's `allowed`,
  `visible`, `available` verbatim; for every other law of the group `OR = { NOT = { has_idea = <it> } AND = {
  <its allowed_to_remove> } }`; `has_political_power > cost - 0.01`; `NOT has_idea = <new>`. Body: `remove_ideas` for
  each other law of the group that is held, `add_ideas = <new>`, `add_political_power = -cost`, a log marker. Refused
  before anything is written: a law the country can never have, a law with no `cost` (a focus or event sets it), a
  condition that reads `FROM`/`PREV`, a cost above the political power the reader sees. Unchecked, reported on the
  result: cost modifiers (the base cost is charged). Unverified in a live game: that `add_ideas` of a law replaces the one
  in its slot is not assumed (the old one is removed first).
* **`fire_advisor`** (`console._plan_fire`). `has_idea = <idea_token>` says the advisor is hired; `deactivate_advisor`
  dismisses; refused when the role says `can_be_fired = no`. Script that changed it since the files is unchecked.
* **`set_occupation_law`** (`policy_effects.plan_occupation_law`). The law's `visible` and `available` in the limit; no
  cost exists. Per-country override wraps the effect in the tag's scope and guards with `any_occupied_country`.
* **`diplomacy_act`** (`policy_effects.plan_diplomacy`). Done: `guarantee`, `leave_faction`. Refused with the reason and
  the route: every act in `DIPLOMACY_REFUSALS`. A test pins that the action enum is exactly those two plus the refusals.
* **Directives** (`modgen.STRATEGIES`). `prepare_war`, `declare_war`, `volunteers`, `lend_lease`, `ally`, `spy_on`,
  `sabotage`, `steal_tech`, on the existing target plumbing: a block per (directive, country), gated on `llmb_<directive>_<TAG>`.
* **`read_event`, `choose_event_option`** (`adapters/event_choice.py`, `modcontext/events.py`, `adapters/ocr.py`). The
  open window is read by Windows OCR and matched to the playset's events; the option is clicked where its text was read.
  Refused with nothing clicked when no window is open, it is not matched, the option is not shown to the country, or the
  game is not in front. Whole story and the live steps: `docs/events.md`.
* **`steer_production`, `steer_intelligence`, `steer_research`, `steer_navy`, `steer_air`, `steer_spending`, `steer_market`, `steer_army`** (`steering.py`). One block per (kind, id, level) in
  `llm_bridge_steering.txt`, one per technology in `llm_bridge_research.txt`, one per strategic region or country in
  `llm_bridge_regions.txt` (the last two generated per playset by `hoi4-harness mod-probe`); the inbox sets the flag, replacing the
  level. The brief lists what stands ("AI steering standing: ..."). Values are the documented scales, a starting point.

## What stays infeasible and why

* **Instant-by-effect.** Focus, research, doctrines, MIOs, agency upgrades, operatives, special projects, factions,
  puppets, peace: the effect exists and does the thing without the time, points or answer the screen needs.
* **Acceptance.** Military access, pacts, faction invitations, lend-lease: the other side's answer is the game, and
  only its AI can give it. The faithful route is to steer the AI (`set_ai_directive`), which the AI carries out with its own
  acceptance.
* **No syntax.** `decrypt_target`, `activate_crypto`, `occupation_policy`, `fuel_buffer`, `wanted_supply_trucks`,
  `wanted_supply_trains`: named in the token list, documented nowhere and used nowhere in the game's own files.
* **Costs no effect charges.** Editing a division template (army experience), cancelling a focus or a research slot, a
  railway (a path, built at once by the only effect), a resource trade, a licence.
* **No scope.** Divisions, task forces and wings have no script scope; the mouse is the only route (`unit_orders`).
