# Overnight 2026-11-22: live verification, then a 1936-1948 campaign

Unattended (the person asleep). Game: HOI4 1.20, vanilla + llm_bridge (scripts/live_setup.py), launched with -debug_mode. Model: Claude Haiku through the Claude Code CLI (`claude -p`, no API key). Every finding below is from the live game unless marked otherwise.

## Phase 1: verification (Spain 1936)

### Run 1 (00:38-00:48): the game crashed at the first weekly tick

Launched hoi4.exe -gdpr-compliant -debug_mode (native.launch_game), menus by mouse (Single Player, New Game, 1936, Spain, Start), `human_ai` and `gamespeed 4` through the console channel. Findings:

1. **No harness country, no inbox.** After `human_ai` the AI owns Spain, so `llm_bridge_is_harness` was false for every country: the daily hook (telemetry and the inbox dispatcher) fired for nobody. One state line, then silence. Marking Spain (`effect SPR llm_bridge_mark_harness`) brought the daily ticks back. In the real rival setup a person plays, and is_ai = no makes their country a harness country; a no-human run must mark a country.
2. **Telemetry verified live:** state, army, focus, research, divend, camp, the weekly intel line, and the new observe lines (res, tension, equip, garrison) with sensible values (Spain: steel 108 produced, 54 exported; infantry equipment 11,889 of 12,490 needed; world tension 4.9).
3. **Intel is already a percentage.** `civilian_intel` and friends read 40/5/30/5, so the mod's x100 gave 4000 and the reader clamped it to 100%: every country would have shown as fully known. Fixed (no multiply).
4. **Crash.** Access violation with a deep recursive stack at 1936.03.29.01, right after the weekly observe effect: its peace-conference block raised "Peace conference trigger is called when there is no active peace conference" three times, then the faction-influence and volunteer blocks (nested every_country with has_volunteers_amount_from on PREV/ROOT). Those blocks are removed; resources, tension, equipment and garrison stay. Some observe lines were logged twice (unexplained).
5. **138 load errors** in `llm_bridge_steer_regions.txt`: `equipment_market_for_sale_factor` takes the game's own category tokens (`armor`, `train`, as CZE.txt and the documentation use), not archetype names. The `sell` market steer is dropped.
6. **The inbox was never acknowledged.** The probe batch sat posted while Spain was marked and its daily hook ran for three days before the crash. Suspected: the writer's tmp + atomic rename is a rename the game's file watcher ignores. The writer now writes in place. To be retested.
7. Focus: VS Code came to the front during the run; the console path's focus guard kept keys out of it.
8. Weekly usage: the Claude Code banner read 77% of the weekly limit at 00:43, so model calls tonight stay lean (Haiku, sparse wakes).

### Run 2 (00:55-): the inbox does not reload; everything else through the console

1. **The inbox does not work live.** With Spain marked, daily ticks flowing (57 state lines) and the writer now writing in place, the probe batch was never acknowledged in 150 s (about 50 in-game days). 1.20's documented console reloads cover the interface, technologies, OOBs and textures, not events or scripted effects, and the game logged no reload of the file. The inbox stays in the code, opt-in (`--transport inbox`); `native` now defaults to the console path (keys) acting in the person's pauses, which is what rival mode verified on 2026-11-21. A new `idle` policy acts whenever the keyboard is idle (unattended runs).
2. **The brief works on live data** (save of 1936-03-01 plus the log): Spain's 17 divisions by state with terrain, org, manpower, dug-in and what each faces; industry; resources; the equipment gap; intel-gated neighbours (civilian intel 40% gave estimated factories, army intel 5% gave only the divisions seen in contact); DLC line.
3. **Bugs seen in the brief:** accented names garbled (the save is not UTF-8: needs a Windows-1252 fallback); world tension shown 0% while the log reads 4.9; the politics view's political power 21.4 against 209 in the log.
4. **Actions confirmed live through the console** (a marker logged inside the guard): `diplomacy_act guarantee POR` ("SPR now guarantees POR"), `set_front_order hold`, `set_region_order dominate` (region 68), `steer_production`. `change_law` refused for 150 PP with 93 held (correct). `take_decision` on a civil-war decision not yet available: unverified, as designed. `design_equipment` refused a design with no main armament (correct), and is not offered when the game's AI owns production.
5. **Every guard that copies a law's or decision's `has_dlc = "Death or Dishonor"` failed on the console** (it splits quoted text on spaces). Fixed: the console channel folds `has_dlc` to `always = yes/no` from the playset's active DLCs before writing.
6. **Region names:** "Western Mediterranean" did not match "Western Mediterranean Sea"; a unique partial name now matches. The LLM has no tool that lists strategic regions yet.
7. **Late countries work live:** `native --rival SPR --breakaway --rival-act-when idle` read "D01 broke away from SPR (democratic)" from the mod's dyn line, started on D01 (the Republic, the AI's Spain having gone the other way), marked it and saw it report.

Haiku through `claude -p`, rival mode on the breakaway, `idle` policy (orders typed whenever the keyboard is idle).

Fixes: a unique prefix now resolves (`synth_oil` -> `synth_oil_experiments`); the rival guidance says to take the suggested id and never resend a rejected guess.

- **Brief observations:** 45 divisions, 28 battles with tactics and an estimated bar, the civil war front by state, industry; accented names garbled until the Windows-1252 fallback (fixed).
- Judgement note: the model set a defensive posture while holding `invade SPR`, then steered with front orders; front orders are the better fit here and the guidance should say that posture and front orders combine (posture = the whole army's stance, front orders = where).

## Phase 2: campaign (Germany 1936-1948)

`play --campaign --profile profiles/overnight-ger-haiku.json --live`: the game's AI plays Germany (`human_ai`), Haiku through `claude -p` steers it at wakes every 45-60 game days, world observer on, recovery saves every six months. Started 01:38 at 1936-01-01.

**Progress at 02:55:** 1938-10-01, 30 states (Anschluss done by the game's AI), 94 divisions, no wars, 23 model calls of about 30k tokens each. That pace is about 2.3 real minutes per game month.

**Actions in the first 33 game months:** 24 `advance_time`, 16 `note`, 11 `inspect_world`, 9 `set_ai_posture`, 4 `set_ai_directive`, 3 `steer_production`, 2 `steer_army`, 1 each of `list_decisions`, `clear_ai_directives` and `take_decision`. No diplomacy was attempted.

**Mistakes:**

- **It believed it was at war when it was not.** The model's text at 1938-10 read "Multi-front war ongoing ~8 months; divisions in active contact across borders confirm CZE/POL/FRA fronts". The brief's war line said "at war with 0", but each neighbour line read "CZE: divisions at least 25 seen (25 in contact)", and the model took "in contact" for a front. Fix: neighbour lines now say "at the border, at peace" or "in contact, at war" (from the save's war relations).
- **declare_war without a war goal.** `set_ai_directive declare_war CZE` stood for 222 days with no war, and the directive-effect line said only "effect not observable with this reader (fronts unknown)". The game's AI declares only with a war goal. Fix: that line now says "not at war yet", and that prepare_war justifies one. The world-conquest pack gains a **War and peace** paragraph.
- **A decision refused for political power** (`GER_reestablish_the_black_reichswehr`: 25 needed, 6.99 held). The game's AI spends PP as it arrives. Fix: both packs now have a **Political power** paragraph (check PP; steer the AI's spending with `steer_spending kind=pp_amount id=idea level=less` before saving for a decision).
- **Reads sent with advance_time.** Five of the first 37 calls paired `inspect_world` with `advance_time`. The harness skips the advance so the model sees the read, which costs a whole extra call of about 30k tokens. The skip message and the tool description named only `list_decisions` / `describe_action`, so the model was never told `inspect_world` counts. Both now name every read.
- **War with Poland on 1939-08-30** (the game's AI, from its own focus path), at 34 states and 127 divisions. The model's text then said "FRA/POL wars ongoing" while the war line read POL only: the same misreading of border contact as above.
- **Too slow to finish by morning.** By 1940 each cycle was a Haiku call of 60-85 s (`claude -p`, about 30k tokens in) plus a 7-15 day advance at speed 4 (about 5 s a game day in a world war). That is 6 real minutes a game month, so 1948 would come around 14:00. At 04:23 the runner was stopped between wakes and resumed (`play --campaign --resume`) with `profiles/overnight-ger-haiku-fast.json`: speed 5 (1.5 s a game day), reviews every 21-30 days in war, 45 in peace. The resume picked up its 58 turns and memory, and loaded tonight's fixes.
- **HOI4 leaks memory: 78 GB private at 1940-10, three hours in.** The system commit was 107.5 of 109 GB. The previous overnight run crashed in 1944 at about the same runtime, now explained. Recovery: the runner was stopped between wakes, the fresh autosave (1940-11-01) copied to `GER_overnight_resume.hoi4`, HOI4 killed and relaunched with `-debug_mode`, the save loaded from the menu (Single Player > Load > the save > Load > Start). `--resume` then found ai=0, marked GER, set `human_ai` and saw ai=1 on the next state line. The whole restart took 6 minutes. The cause is not known: the game itself, `-debug_mode`, the daily probe effect's logging, or the console's `run` file. The harness should do this itself: watch hoi4.exe's private bytes and, past a limit, save, restart and reload at the next wake (to build).
- **Memory guard (built after the restart).** `campaign_memory_limit_gb` (48 by default) is checked at each turn against hoi4.exe's private bytes. Past it, the run takes a recovery save at once and stops resumably, with the restart steps in the stop reason (`campaign_on_memory: warn` only logs instead). It reads 9.5 GB live ten minutes after a fresh load.
- **The guard fired live** at 06:04 (49 GB, 1942-06-27): it took a recovery save and stopped with the restart steps. A first automatic restart (a script outside the harness) failed safely but uselessly. The relaunched game stayed behind VS Code, so the menu clicks landed in VS Code (no keys typed). Stopping that script also killed the game it had launched (same process tree). Fixes: the script now checks that the game window is in front before every click and stops if it is not; it starts the game and the runner through WMI, outside its own tree; and it waits up to five minutes for the window. `campaign_take_focus` gained `campaign_take_focus_idle_seconds` (120): it pulls the game to the front only after two minutes with no keyboard or mouse input. The restart was finished by hand at 06:17 (1942-06-28).
- **Budget stop at 1940-12-19:** the default output-token ceiling (400k) ran out after 68 calls. Haiku writes about 6k output tokens a wake (long reasoning text with its tool calls). It was a clean, resumable stop. The fast profile now sets 1.2M output and 12M input, and caps a call at 4k output; the run was resumed at once.
- **Barbarossa, 1941.** From 1941-01 the model wanted war with the USSR. It held `prepare_war` and `declare_war SOV` directives at weight 10, then 20, and sent `diplomacy_act declare_war SOV` four times, refused each time ("declare_war has no faithful effect"). By 1941-04-28 it had `describe_action GER_war_with_the_ussr`, found that the focus grants the war goal, and wrote "Barbarossa locked to focus completion". It got there itself, but only after about 100 game days and several wasted calls. Guidance now says that historical wars often come from a focus, to describe it, and to wait. The re-sent refusal is the same habit as the invented research ids: it does not take a refusal as final.
- **Invented PP bleed.** The model wrote "PP at critical 18 with -13/day garrison bleed (44 states x ~10k manpower)". Nothing in the brief said that: garrisons cost manpower and equipment, not PP. The brief now gives the measured net trend (live: PP 4.8, net -0.06/day over 30 days, so the AI spends what it gains). The model had also set `pp_amount idea less` after the new paragraph, which is the right lever.
- **Steer ids from the brief's own Industry line** (`medium_tank_chassis`, `infantry_equipment_2`) were refused. They now map to `armor` and `infantry`. `small_plane_airframe` stays refused with the list, since fighter or CAS is ambiguous.
- **The per-turn cap (8 actions)** dropped six `set_front_order` calls in one turn. That is fine as a cap; the model learned nothing from it.
- **1942-1943: it gave up.** From October 1942 every turn opened with "Campaign mathematically impossible/failed (3.1% world, need 11+/mo)". It took notes and advanced time while the war with the USSR sat at 0% surrender (1943-10: 251 own divisions against 1,349 enemy in contact states; owned states 58 and controlled 87, 424 divisions). It did call one useful thing: a `hold` order on Riga, a losing attack (359 damage dealt against 3,939 taken over 114 days). Guidance now has **When the objective is out of reach**: play for the best reachable result.
- **Still refused after the fixes:** `motorized_equipment` and `anti_tank_equipment`. The alias step ran only in the console planner, after the identifier check had already refused them; it now runs at the check too. Also `civilian_oversight` (the real one is `foreign_civilian_oversight`) and region `baltic_sea` (Lower Baltic Sea). Both now match a unique part, and a region refusal lists near names.
- **After a reload, war lines read "already on when telemetry began":** the log restarts with the game, so the wars' dates are gone (the save has them; not fixed).
- **Run 2's "PP 21.4 against 209" and "tension 0%" were not bugs.** On 1939-01-01 the save's `politics.political_power` and the log's `pp` both read 64.93, and tension logged 26.28 shows as 26%. Run 2 compared a save from 1936-03-01 with the log's later days. The brief does mix two clocks, though: the save's date for forces and politics, and the log's for the daily numbers.
- **Steer ids it guessed:** `motorized_equipment`, `oil_refinery`. Fix: `steering.normalise` (strips `_equipment`, applies aliases such as oil_refinery -> synthetic_refinery). The running campaign still uses the code it loaded at 01:38, so these fixes apply from the next run.
